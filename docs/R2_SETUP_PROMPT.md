# برومبت الإكستنشن: تجهيز Cloudflare R2 لصور الصيانة

**Trigger:** «ابعتلي برومبت تجهيز R2».

الإكستنشن بيشتغل فى متصفح المالك على حسابه الحقيقى، فالبرومبت فيه خطوط حمرا
صريحة: السرّ مايتكتبش فى الشات، الباكِت يفضل خاص، التوكن على باكِت واحد بس،
وممنوع لمس أى إعداد تانى فى كلاودفلير (DNS/Workers/Proxy — دول وقّعوا الموقع قبل كده).

الحارس: `node scripts/check-r2-prompt.js` — بيربط أسماء الأسرار والصلاحية
المطلوبة بالكود، فأى سرّ جديد فى `utils/r2.js` مش فى البرومبت بيوقّع الفحص.

---

```
أنت شغّال فى متصفح المالك على حسابه الحقيقى فى Cloudflare و Replit.
المطلوب: تجهيز تخزين Cloudflare R2 لصور الصيانة، وحطّ أربع أسرار فى Replit.
مفيش أى كود هيتكتب — الكود اتظبّط خلاص.

── السياق ─────────────────────────────────────────────────────────────
موقع Service Flow فيه قسم صيانة، وفنى الصيانة بيرفع صور للبوكسات. الصور دى
(١٧٤٨ صورة، ٧٥٦ ميجا) مخزّنة دلوقتى جوّه عمود BYTEA فى قاعدة PostgreSQL،
وبيمثّلوا ٦٢٪ من حجم القاعدة كلها (١.٢٦ جيجا) — وده بيكلّف فلوس فى استضافة
القاعدة. الكود اتعدّل خلاص عشان يحطّ الصور على Cloudflare R2 بدل القاعدة.

R2 مناسب هنا لأن الخروج (egress) مجانى تماماً، والباقة المجانية ١٠ جيجا تخزين
و١ مليون عملية كتابة و١٠ مليون عملية قراءة فى الشهر — والاستخدام هنا أقل من
ده بكتير، يعنى التكلفة المتوقّعة صفر.

⚠️ كلاودفلير بتطلب كارت دفع مسجّل قبل ما تفعّل R2 حتى على الباقة المجانية.
لو ظهرت شاشة بتطلب كارت أو تأكيد اشتراك → **قف واسأل المالك**، متكملش لوحدك.

الكود من غير الأسرار دى بيشتغل بالظبط زى ما هو دلوقتى (الصور تفضل فى القاعدة)،
فمفيش أى استعجال ومفيش حاجة هتتكسر لو وقفت فى النص.

── المطلوب منك ────────────────────────────────────────────────────────

١) إنشاء الباكِت
   - افتح dash.cloudflare.com واتأكد إنك داخل بحساب المالك.
   - من القايمة الجانبية افتح R2 (ممكن تلاقيها باسم «R2 Object Storage»).
   - اضغط «Create bucket».
   - الاسم: serviceflow-maintenance
     (حروف صغيرة وأرقام وشرطات بس، من ٣ لـ٦٣ حرف).
   - الموقع (Location): سيب «Automatic».
   - 🔴 سيب الباكِت **خاص**. متفعّلش «Public access» / «Allow Access»
     ولا تربطه بـcustom domain ولا r2.dev. القراءة بتعدّى من السيرفر نفسه،
     فالصور لازم تفضل مش مفتوحة للعالم.

٢) إنشاء API Token
   - من صفحة R2، افتح «Manage API Tokens» (أو «API» ← «Create API Token»).
   - نوع التوكن: **Object Read & Write** — مش «Admin Read & Write».
   - النطاق: اختار «Apply to specific buckets only» وحدّد
     **serviceflow-maintenance بس**. متديهوش صلاحية على كل الباكِتس.
   - TTL: من غير انتهاء (forever) لو متاح.
   - اضغط Create.

٣) الأربع قيم اللى هتطلع
   بعد الإنشاء هتظهر الصفحة بالقيم دى:
   - Access Key ID
   - Secret Access Key  ← 🔴 **بيظهر مرة واحدة بس. لو قفلت الصفحة راح.**
   - الـEndpoint بالشكل: https://<account_id>.r2.cloudflarestorage.com
     الجزء اللى قبل .r2 هو الـAccount ID. (موجود برضه فى الشريط الجانبى
     فى صفحة R2 الرئيسية.)

٤) حطّهم فى Replit Secrets — 🔴 **فى المشروع الصح**
   فيه نشرتين لـService Flow شغّالين مع بعض على نفس القاعدة:
     • المشروع **القديم** المستقل (اسمه «Service Flow»)
     • ونشر **أوسكار ديفز** اللى Service Flow متستضاف جوّاه

   **كود R2 موجود فى نشر أوسكار ديفز بس.** حطّ السرّ فى المشروع القديم =
   مش هيعمل أى حاجة خالص، لأن الكود هناك أصلاً مافيهوش R2.

   ازاى تعرف المشروع الصح **من غير تخمين**: افتح Secrets وشوف. المشروع الصح
   فيه المتغيّرات دى:
       SERVICEFLOW_UPSTREAM · SERVICEFLOW_HOST · SERVICEFLOW_DATABASE_URL
   لو مالقتهمش، إنت فى المشروع القديم — **اقفله وافتح التانى**، ولو مش
   لاقيه اسأل المالك.

   وبعدين ضيف الأربعة دول بأسمائهم بالظبط حرف بحرف:

     R2_ACCOUNT_ID         = الـaccount id من الـendpoint
     R2_ACCESS_KEY_ID      = الـAccess Key ID
     R2_SECRET_ACCESS_KEY  = الـSecret Access Key
     R2_BUCKET             = serviceflow-maintenance

   - 🔴 الأربعة لازم يكونوا موجودين **مع بعض**. لو واحد ناقص أو فيه مسافة
     زيادة، النظام بيرجع يخزّن الصور فى القاعدة من غير أى رسالة خطأ —
     يعنى هتفتكر إنه شغّال وهو مش شغّال.
   - متضيفش أى سرّ تانى ومتعدّلش أى سرّ موجود.

── 🚫 خطوط حمرا ───────────────────────────────────────────────────────
- **الـSecret Access Key متكتبهوش فى الشات، ولا فى أى ملف، ولا فى أى خانة
  غير خانة Replit Secret نفسها.** ومتصوّرش الشاشة وهو ظاهر.
- متفعّلش Public Access على الباكِت ولا تربطه بدومين.
- التوكن يفضل Object Read & Write على الباكِت ده بس — مش Admin.
- **متلمسش أى إعداد تانى فى كلاودفلير خالص** — خصوصاً DNS والسحابة
  البرتقالى/الرمادى والـWorkers والـPage Rules. أى تغيير هناك بيوقّع الموقع
  كله (حصل قبل كده).
- متعملش Republish ولا Deploy فى ريبليت. المالك هو اللى بيعمله بنفسه.
- متعدّلش أى ملف كود ولا تفتح Replit Agent.
- لو أى شاشة طلبت كارت دفع أو تأكيد شراء أو ترقية باقة → **قف واسأل**.

── التقرير فى الآخر ───────────────────────────────────────────────────
قول بالظبط:
- الباكِت اتعمل باسم إيه، وهو خاص ولا عام.
- التوكن نوعه إيه، ومربوط بأنهى باكِت.
- الأربع أسرار اتحطّت فى Replit ولا لأ — **من غير ما تكتب قيمة أى واحد فيهم**.
- أى خطوة وقفت فيها وليه.
```

## برومبت التصحيح — لو الإكستنشن بدأ فى المشروع الغلط

حصل فعلاً: الإكستنشن حطّ `R2_ACCOUNT_ID` فى مشروع **Service Flow** القديم،
واللى مافيهوش كود R2 خالص — يعنى السرّ اتحطّ ومحصلش أى حاجة. ابعتله ده
وهو شغّال عشان يوقف ويصحّح المسار.

```
قف. إنت بتحطّ الأسرار فى المشروع الغلط.

فيه نشرتين لـService Flow شغّالين مع بعض على نفس قاعدة البيانات:
  • مشروع «Service Flow» القديم المستقل — ده اللى إنت فيه دلوقتى
  • ومشروع «sf» — نشر أوسكار ديفز اللى Service Flow متستضاف جوّاه

كود Cloudflare R2 موجود فى **sf** بس. المشروع القديم كوده مافيهوش R2 من
أصله، فأى سرّ تحطّه هناك مش هيعمل أى حاجة — لا هيظهر خطأ ولا هيشتغل.

المطلوب منك دلوقتى:

١) بطّل شغل فى المشروع القديم فوراً.

٢) 🔴 متمسحش أى سرّ بإيدك. لو كنت ضفت أى R2_* هناك سيبه زى ما هو وقول
   للمالك أسماء اللى ضفتها بالظبط (من غير قيمها) عشان هو يشيلها بنفسه.
   وقول له صريح لو كنت وصلت لـR2_SECRET_ACCESS_KEY وحطّيته هناك.

٣) افتح مشروع **sf** واتأكد إنه الصح **بالدليل مش بالاسم**: افتح Secrets
   ودوّر على التلاتة دول:
       SERVICEFLOW_UPSTREAM
       SERVICEFLOW_HOST
       SERVICEFLOW_DATABASE_URL
   موجودين؟ يبقى ده المشروع الصح، كمّل.
   مش موجودين؟ **قف واسأل المالك** — متحطّش أى حاجة على أساس الاسم لوحده.

٤) فى مشروع sf، ضيف الأربعة دول بأسمائهم حرف بحرف:

     R2_ACCOUNT_ID         = الـaccount id من endpoint الـR2
     R2_ACCESS_KEY_ID      = الـAccess Key ID
     R2_SECRET_ACCESS_KEY  = الـSecret Access Key
     R2_BUCKET             = serviceflow-maintenance

   الأربعة لازم يكونوا مع بعض. واحد ناقص أو فيه مسافة زيادة = النظام بيرجع
   يخزّن الصور فى القاعدة **من غير أى رسالة خطأ**.

٥) لو الـSecret Access Key ضاع منك (بيظهر مرة واحدة بس): متحاولش تجيبه.
   ارجع لـCloudflare R2 واعمل توكن **جديد** بنفس المواصفات
   (Object Read & Write، على باكِت serviceflow-maintenance بس)، واستعمل
   قيمه الجديدة.

🚫 الخطوط الحمرا زى ما هى:
- الـSecret Access Key متكتبهوش فى الشات ولا فى أى ملف — خانة Secret بس.
- متعملش Republish ولا Deploy. المالك هو اللى بيعمله.
- متعدّلش أى كود ولا تفتح Replit Agent.
- متلمسش أى إعداد فى كلاودفلير غير اللى فوق — خصوصاً DNS والـWorkers.

التقرير فى الآخر: إنت كنت فى أنهى مشروع، إيه اللى ضفته فيه (أسماء بس)،
وإيه اللى ضفته فى sf — من غير ما تكتب قيمة أى سرّ.
```

## برومبت المراجعة — «إيه اللى اتعمل فعلاً؟»

يتبعت بعد ما الإكستنشن يقول إنه خلّص. بيراجع بالدليل، **ومايدّعيش** إن R2
شغّال — ده مايتأكّدش غير بعد Republish ورفع صورة، ودى خطوة المالك.

```
خلاص، بلاش تضيف أى حاجة جديدة. عايزك دلوقتى **تراجع** اللى اتعمل وتقولى
النتيجة بالدليل. متصلّحش أى حاجة من نفسك — لو لقيت مشكلة قولها وبس.

── أ) الأهم: الكود المنشور فيه R2 أصلاً؟ ──────────────────────────────
ريبليت بيبنى اللى فى الـworkspace بتاعه، **مش** اللى على جيت‌هَب. فنشر من
غير Git Sync الأول بيبنى كود قديم — والإعداد كله يبقى صح والنتيجة صفر.

افتح تبويب **Shell** فى مشروع sf ونفّذ الأمرين دول (قراءة بس):

    git log --oneline -3
    ls serviceflow/server/maintenance/app/utils/r2.js

قولى الناتج. لازم تلاقى كوميت عنوانه فيه «Cloudflare R2»، والملف `r2.js`
موجود. لو مش موجودين → الـworkspace لسه قديم: افتح تبويب **Git** واعمل
**Sync/Pull**، وبعدها المالك يعمل Republish. قول له ووقف.

── ب) الاختبار الحى لـR2 ──────────────────────────────────────────────
لو الكود موجود، نفّذ الأمر ده فى نفس الـShell:

    node serviceflow/scripts/migrate-photos-to-r2.cjs --check

ده بيرفع كائن صغير على R2 ويقراه ويقارنه **ويمسحه** — مابيلمسش ولا صورة
ولا القاعدة. انسخلى الناتج كامل زى ما هو.
  • «✅ R2 شغّال» = الأسرار موجودة وصحيحة فعلاً. دى أقوى نتيجة ممكنة.
  • «✖ أسرار ناقصة» = هيقولك اسم الناقص بالظبط.
  • «✖ الرفع فشل … 403» = مفتاح غلط أو التوكن مش على الباكِت ده.
  • «✖ الرفع فشل … 404» = اسم الباكِت غلط.

── ج) فى ريبليت، مشروع sf ─────────────────────────────────────────────
افتح Secrets فى مشروع sf (replit.com/@menoskar42/sf).

١) اتأكد الأول إنك فى المشروع الصح: التلاتة دول لازم يكونوا موجودين
   SERVICEFLOW_UPSTREAM · SERVICEFLOW_HOST · SERVICEFLOW_DATABASE_URL
   (فلتر بكلمة SERVICEFLOW). لو ناقص منهم حاجة قول وقف.

٢) فلتر بكلمة R2 وقولى الأربعة دول موجودين ولا لأ، **بالاسم بالظبط**:
       R2_ACCOUNT_ID
       R2_ACCESS_KEY_ID
       R2_SECRET_ACCESS_KEY
       R2_BUCKET
   دوّر على غلطات الاسم الشائعة: حرف ناقص، شرطة سفلية زيادة أو ناقصة،
   حروف صغيرة، أو مسافة فى آخر الاسم. أى اختلاف حرف واحد = السرّ مش
   هيتقرا خالص.

٣) 🔴 مهم: ريبليت بيحذّر لما يبقى فيه «Account Secret» بنفس اسم
   «Project Secret» — وساعتها **قيمة الـAccount Secret هى اللى بتتغلّب**.
   بصّ على كل واحد من الأربعة: فيه عليه علامة ربط (🔗) أو تحذير تعارض
   أسماء؟ قولى بالظبط أى واحد فيهم متأثّر. ده بيخلّى السرّ يبان موجود
   وقيمته اللى بتوصل للتطبيق حاجة تانية خالص.

٤) قيمة R2_BUCKET بس — دى مش سرّ — افتحها وقولى هى إيه بالحرف.
   لازم تطابق اسم الباكِت اللى فى كلاودفلير حرف بحرف.

🚫 R2_ACCESS_KEY_ID و R2_SECRET_ACCESS_KEY: **متفتحهمش ومتكتبش قيمتهم**
   فى الشات ولا فى أى مكان. قول «موجود وقيمته مش فاضية» وبس.

── د) فى كلاودفلير ────────────────────────────────────────────────────
٥) الباكِت موجود؟ قولى اسمه بالحرف.
٦) هو **خاص** ولا عام؟ افتح إعداداته وشوف: فيه Public Development URL
   (r2.dev) مفعّل؟ فيه custom domain متربوط؟ المفروض **لأ فى الاتنين**.
٧) التوكن: نوعه إيه (لازم يكون Object Read & Write مش Admin)، ومربوط
   بأنهى باكِت (لازم الباكِت ده بس مش All buckets)؟
٨) قارن الـAccount ID اللى فى كلاودفلير بقيمة R2_ACCOUNT_ID اللى فى
   ريبليت — **من غير ما تكتب القيمة**. قول «متطابقين» أو «مختلفين».
٩) اشتراك R2 مفعّل؟ وTotal Due Now قيمته كام؟

── هـ) حاجة لازم تقولها بصراحة ────────────────────────────────────────
١٠) لو كنت ضفت أى R2_* فى مشروع «Service Flow» القديم قبل كده، قولى
    أسماءها (من غير قيم)، وقولى صريح لو كان من ضمنها R2_SECRET_ACCESS_KEY.
    **متمسحش أى حاجة** — المالك هو اللى هيشيلها.

── التقرير ────────────────────────────────────────────────────────────
اكتبلى قايمة بكل بند، كل واحد قدامه ✅ أو ❌ وسطر واحد بالدليل اللى
شُفته. وابدأ ببند الكود والاختبار الحى — دول الأهم. وفى الآخر سطر واحد: «كله تمام» أو «فيه مشكلة فى بند رقم كذا».

⚠️ ومهم: لو `--check` ما اشتغلش أو ما طلعش ✅، **متقولش إن R2 شغّال**
مهما كانت الأسرار مظبوطة فى الشاشة. سرّ موجود ≠ سرّ صحيح. أقصى حاجة
تقولها ساعتها: «الإعداد مكتمل، وفاضل التأكيد الحى».

🚫 متعملش Republish ولا Deploy، ومتعدّلش أى سرّ ولا كود، ومتلمسش أى
إعداد تانى فى كلاودفلير.
```

## برومبت الإنهاء — الأسرار مش موجودة والمفتاح ضاع

نتيجة المراجعة (٢٠٢٦-٠٩-٢٢): الكود موجود فى الـworkspace ✅، التوكن اتعمل
صح على كلاودفلير ✅، **بس الأربع أسرار ما اتحطّوش فى أى مكان** ❌ —
و`--check` قال «أسرار ناقصة» للأربعة. ومفتاح التوكن بيظهر مرة واحدة، فهو
ضاع ولازم يتعمل Roll.

⚠️ افتح للإكستنشن تبويب Cloudflare الأول — فى المراجعة الأخيرة مكانش عنده
وصول للحساب.

```
المراجعة بتاعتك طلعت النتيجة دى: الكود موجود فى الـworkspace، والتوكن
اتعمل صح على كلاودفلير، بس **الأربع أسرار ما اتحطّوش فى ريبليت خالص**.
ومفتاح التوكن (Secret Access Key) بيظهر مرة واحدة بس وقت إنشائه — يعنى
ضاع. مفيش طريقة تجيبه، لازم يتعمل من جديد.

المطلوب منك دلوقتى، بالترتيب:

١) افتح Cloudflare ← R2 Object Storage ← Manage API Tokens.
   هتلاقى تحت «Account API Tokens» توكن اسمه: serviceflow-maintenance-rw
   (Applied to: serviceflow-maintenance · Permission: Object Read & Write)

٢) من قايمة «...» اللى جنبه اختار **Roll** (تجديد المفتاح).
   لو مفيش Roll، اعمل **Create Account API token** جديد بنفس المواصفات
   بالظبط:
       Permission: Object Read & Write   (مش Admin)
       Scope: Apply to specific buckets only ← serviceflow-maintenance بس
       TTL: forever
   وسيب القديم زى ما هو، المالك هو اللى هيمسحه بعدين.

٣) 🔴 الصفحة اللى هتظهر بعدها فيها Access Key ID و Secret Access Key،
   **والسيكريت بيظهر مرة واحدة بس.** متقفلش الصفحة دى قبل ما تخلص
   خطوة ٤. ومتكتبش قيمته فى الشات ولا فى أى ملف.

٤) روح على ريبليت مشروع **sf** (replit.com/@menoskar42/sf) ← Secrets،
   واضغط «New Secret» أربع مرات وضيف دول بأسمائهم حرف بحرف:

       R2_ACCOUNT_ID         = c8a1a2adaad0b602e645dde88a959d0b
       R2_ACCESS_KEY_ID      = من الصفحة اللى فى خطوة ٣
       R2_SECRET_ACCESS_KEY  = من الصفحة اللى فى خطوة ٣
       R2_BUCKET             = serviceflow-maintenance

   (الـaccount id ده ظاهر فى لينك كلاودفلير نفسه — اتأكد إنه مطابق.)
   حطّهم كـ**Secrets** مش Configurations، ومن غير مسافات فى الأول أو الآخر.

٥) افتح تبويب **Shell** فى نفس المشروع ونفّذ:

       node serviceflow/scripts/migrate-photos-to-r2.cjs --check

   لازم يطلع «✅ R2 شغّال». انسخلى الناتج كامل.

   لو طلع 404 → اسم الباكِت غلط.

٦) وإنت فى كلاودفلير، راجع بند فاتنا: افتح إعدادات الباكِت
   serviceflow-maintenance وقولى هو **خاص** ولا لأ — يعنى فيه Public
   Development URL (r2.dev) مفعّل؟ وفيه custom domain متربوط؟
   المفروض **لأ فى الاتنين**.

٧) وبند تانى: فى Secrets وConfigurations بتوع sf، دوّر على
   SERVICEFLOW_HOST. إنت قلت إنه مش موجود فى الـSecrets — بصّ كمان فى
   قسم **Configurations** وفى قيم «published app value». قولى لقيته فين،
   ولو مش موجود خالص فى الاتنين قول كده صريح. **متضيفهوش من عندك.**

🚫 الخطوط الحمرا:
- الـSecret Access Key متكتبهوش فى الشات ولا فى أى ملف — خانة Secret بس.
- متعملش Republish ولا Deploy — المالك هو اللى بيعمله بعد ما تخلص.
- متعدّلش أى كود، ومتمسحش أى سرّ أو توكن قديم.
- متلمسش DNS ولا Workers ولا أى إعداد تانى فى كلاودفلير.

التقرير: الخطوات من ١ لـ٧ كل واحدة ✅ أو ❌، وناتج --check كامل، ومن غير
ما تكتب قيمة أى سرّ.
```

## برومبت «كل حاجة ما عدا اللصقتين»

الإكستنشن بيرفض يلمس `R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY` — ودى
مفاتيح فعلاً، فالرفض سليم ومش متناقض مع إنه حطّ `R2_ACCOUNT_ID` قبل كده
(ده رقم حساب ظاهر فى اللينك، مش مفتاح).

البرومبت ده بيخلّيه يعمل **كل** الباقى: السرّين اللى مش أسرار، فتح صفحة
التوكن، وبعد ما المالك يلزق المفتاحين بإيده — الاختبار الحى والمراجعة.

```
أنا فاهم إنك مش هتلمس Access Key ID ولا Secret Access Key، وده تمام —
المالك هو اللى هيلزقهم بإيده. عايزك تعمل **كل حاجة تانية**، وتقف عند
اللصقتين دول بس.

── ١) السرّين اللى مش أسرار ────────────────────────────────────────────
دول مش مفاتيح: R2_ACCOUNT_ID رقم حساب ظاهر فى لينك كلاودفلير نفسه،
وR2_BUCKET اسم باكِت. ضيفهم دلوقتى فى Replit مشروع sf ← Secrets:

    R2_ACCOUNT_ID  =  c8a1a2adaad0b602e645dde88a959d0b
    R2_BUCKET      =  serviceflow-maintenance

لو أى واحد فيهم موجود بالفعل، سيبه وقول كده.

── ٢) جهّز الشاشتين للمالك ─────────────────────────────────────────────
سيب تاب Replit مفتوح على Secrets فى sf وجاهز على «New Secret».
وافتح فى تاب تانى: Cloudflare ← R2 Object Storage ← Manage API Tokens،
ووقف عند التوكن serviceflow-maintenance-rw. **متدوسش Roll ولا Create**
ومتلمسش أى قيمة — سيبها للمالك.

قول له: «الشاشتين جاهزين. دوس Roll، وهيظهرلك Access Key ID و Secret
Access Key مرة واحدة بس — الزقهم فى ريبليت باسم R2_ACCESS_KEY_ID و
R2_SECRET_ACCESS_KEY قبل ما تقفل الصفحة». وبعدين **استنى** لحد ما يقولك خلص.

── ٣) بعد ما يقولك خلص — الاختبار الحى ────────────────────────────────
افتح تبويب Shell فى sf ونفّذ:

    node serviceflow/scripts/migrate-photos-to-r2.cjs --check

الأمر ده مابيعرضش ولا مفتاح — بيرفع كائن صغير على R2 ويقراه ويمسحه.
انسخلى الناتج كامل.
  «✅ R2 شغّال»      → تمام
  «✖ … 403»         → المفتاح ناقص حرف أو فيه مسافة وقت اللصق
  «✖ … 404»         → اسم الباكِت غلط
  «✖ أسرار ناقصة»   → واحد منهم ما اتسجّلش فعلاً

── ٤) البندين اللى لسه مفتوحين ────────────────────────────────────────
أ) افتح إعدادات الباكِت serviceflow-maintenance وقولى هو **خاص** ولا لأ:
   فيه Public Development URL (r2.dev) مفعّل؟ فيه custom domain متربوط؟
   المفروض **لأ** فى الاتنين.
ب) دوّر على SERVICEFLOW_HOST فى sf — مش فى الـSecrets بس، دوّر كمان فى
   قسم **Configurations** وفى قيم «published app value». قولى لقيته فين،
   ولو مش موجود خالص قول كده صريح. **متضيفهوش من عندك.**

🚫 الخطوط الحمرا:
- متعملش Republish ولا Deploy — المالك هو اللى بيعمله بعد ما تخلص.
- متعدّلش أى كود، ومتمسحش أى سرّ أو توكن.
- متلمسش DNS ولا Workers ولا أى إعداد تانى فى كلاودفلير.

التقرير: كل بند ✅ أو ❌، وناتج --check كامل، من غير ما تكتب قيمة أى سرّ.
```

## برومبت التصغير — الطريق اللى مفيهوش ولا مفتاح

لو R2 اتعطّل لأى سبب، ده بيوصل لنفس الهدف (قاعدة أصغر) **من غير كلاودفلير
ولا توكن ولا لصق أى سرّ**. أوامر شِل بس — فمفيش حاجة يرفضها الإكستنشن.

```
مهمة واحدة بس، كلها أوامر فى الـShell. **مفيش أى سرّ ولا مفتاح ولا

السياق: صور الصيانة ٧٥٦ ميجا جوّه قاعدة PostgreSQL، ومتوسط الصورة ٤٣٢
كيلو — أكبر من اللازم لصورة بوكس متصوّرة بموبايل. فيه سكريبت بيعيد ضغطها
مكانها فى القاعدة.

١) افتح مشروع sf على ريبليت (replit.com/@menoskar42/sf) ← تبويب **Git**
   ← اعمل **Sync/Pull** عشان تجيب آخر كود. (ريبليت بيبنى اللى عنده، مش
   اللى على جيت‌هَب.)

٢) افتح تبويب **Shell** ونفّذ:

       ls serviceflow/scripts/shrink-photos.cjs

   لازم يلاقى الملف. لو مالقهوش، الـSync ما اشتغلش — قول ووقف.

٣) نفّذ ده (قراءة بس — **مابيكتبش أى حاجة فى القاعدة**):

       node serviceflow/scripts/shrink-photos.cjs --dry

   ده بياخد عيّنة عشوائية من الصور، **بيضغطها فعلاً** فى الذاكرة، ويقول
   الأرقام اللى طلعت حقيقى. انسخلى الناتج كامل زى ما هو.

   ⚠️ أول سطر بيقول اسم القاعدة. لازم يكون فيه عدد صور بالمئات أو الآلاف.
   لو طلع «مفيش جدول photos» أو عدد صفر → قاعدة غلط، **قول ووقف**.

٤) **استنى موافقة المالك** على الأرقام قبل أى تنفيذ. متشغّلش الأمر من
   غير --dry من نفسك.

٥) بعد ما يوافق بس، نفّذ:

       node serviceflow/scripts/shrink-photos.cjs

   وانسخلى الناتج كامل. ممكن ياخد وقت — سيبه يخلّص.

🚫 متعملش Republish، متعدّلش أى كود ولا أى سرّ، ومتشغّلش أى أمر تانى غير
اللى فوق. ولو أى أمر طلب منك بيانات دخول، وقف واسأل — المفروض مايحصلش.
```

## برومبت R2 النهائى — مصمَّم يشتغل حتى لو رفض يلمس المفتاح

الإكستنشن رفض قبل كده يتعامل مع `R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY`.
البرومبت ده **مابيحاولش يقنعه** — بيقوله من أول سطر: لو مش هتلمسهم قول
دلوقتى وكمّل الباقى. كده الشغل بيمشى فى الحالتين بدل ما يقف.

```

🔸 قبل ما تبدأ — اقرا ده:
فيه خطوة واحدة جوّه المهمة دى فيها نسخ Access Key ID و Secret Access Key.
لو ده مخالف لحدودك، **قول كده فى أول رد** وكمّل باقى الخطوات عادى، وسيب
اللصقتين دول للمالك. **متقفش المهمة كلها عشانهم، ومتحاولش تلفّ حواليهم.**
كل الخطوات التانية مفيهاش أى بيانات دخول.

── ١) السرّين اللى مش مفاتيح (اعملهم على طول) ──────────────────────────
دول مش بيانات دخول: الأول رقم حساب ظاهر فى لينك كلاودفلير نفسه، والتانى
اسم باكِت. ضيفهم فى Replit مشروع **sf** (replit.com/@menoskar42/sf) ←

⚠️ اتأكد إنك فى المشروع الصح: لازم تلاقى SERVICEFLOW_UPSTREAM و
SERVICEFLOW_DATABASE_URL فى نفس اللوحة. لو مش موجودين، إنت فى مشروع
«Service Flow» القديم — ده مافيهوش كود R2 خالص، اقفله وافتح sf.

── ٢) المفتاحين ───────────────────────────────────────────────────────

(Object Read & Write، على باكِت serviceflow-maintenance بس).

لو **هتعملها**: المفتاح بيظهر مرة واحدة بس وقت الإنشاء. لو ضاع، افتح

لو **مش هتعملها**: افتح الشاشتين وسيبهم جاهزين — تاب على Manage API
Tokens من غير ما تدوس Roll، وتاب على Secrets فى sf. وقول للمالك:
«الشاشتين جاهزين، دوس Roll والزق القيمتين». **واستنى لحد ما يقولك خلص.**

── ٣) الاختبار الحى (اعملها فى الحالتين) ──────────────────────────────
لما الأربعة يبقوا موجودين، افتح تبويب **Shell** فى sf ونفّذ:

    node serviceflow/scripts/migrate-photos-to-r2.cjs --check

الأمر ده **مابيعرضش ولا مفتاح** — بيرفع كائن صغير على R2 ويقراه ويمسحه.
انسخلى الناتج كامل.

── ٤) بندين لسه محدّش شافهم ───────────────────────────────────────────
أ) افتح إعدادات الباكِت serviceflow-maintenance: فيه Public Development
   URL (r2.dev) مفعّل؟ فيه custom domain متربوط؟ المفروض **لأ** فى
```

## برومبت تنفيذ التصغير (بعد موافقة المالك على أرقام --dry)

قياس حقيقى من ٢٠٢٦-٠٩-٢٢ على قاعدة Service Flow: **١٧٥٨ صورة · ٧٦١.٧ ميجا ·
متوسط ٤٤٤ كيلو**. عيّنة ٤٠ صورة اتضغطت فعلاً → **٥٥٪ أقل، وولا صورة اتخطّت**.
المتوقّع: ٧٦١.٧ → **٣٤٦ ميجا** (توفير ٤١٥.٦ ميجا).

```

       node serviceflow/scripts/shrink-photos.cjs

   ممكن ياخد وقت طويل (١٧٥٨ صورة). **سيبه يخلّص ومتقطعوش.** لو الشِل

   حيث وقف ومابيعيدش صورة اتصغّرت (شرط `length(data) >= 120k` بيستبعدها
   لوحده)، فمفيش ضرر من إعادة التشغيل.

   انسخلى الناتج كامل.

٢) المساحة مابترجعش للقرص لوحدها — PostgreSQL بيسيب الصفوف القديمة
   كـdead tuples. نفّذ ده بعد ما يخلّص:

       psql "$SERVICEFLOW_DATABASE_URL" -c "VACUUM (FULL, ANALYZE) maintenance.photos"

   ⚠️ الأمر ده بياخد قفل حصرى على الجدول لدقيقة أو اتنين — يعنى الصور

       node serviceflow/scripts/shrink-photos.cjs --dry

٤) وافتح موقع الصيانة واضغط على صورتين تلاتة قديمة واتأكد إنهم بيتعرضوا

🚫 متعملش Republish، متعدّلش أى كود، ومتشغّلش أى أمر تانى غير اللى فوق.
```

التعديلات. فحجم `VACUUM FULL` مش بيظهر فوراً — بينزل بعد ما نافذة
الاحتفاظ بالتاريخ (history retention) تعدّى.

## برومبت نقل الصور القديمة على R2 — التنفيذ الكامل

المالك فوّض (٢٠٢٦-٠٩-٢٢): «انقل الصور انت ولو عاوز حاجة خلّى الإكستنشن يعملها».
فالبرومبت ده بيخلّى الإكستنشن يعمل Republish كمان — **بشرط** شاشة الـGenerated
migrations تكون فاضية من أى DROP.

اتجرّب كله قبل ما يتبعت على PostgreSQL 16 حقيقى + R2 وهمى + `app.js` الحقيقى
بـExpress 5.2.1: رفع بيكمّل بعد صورة فاشلة، `--verify` بيلقط صورة متبوّظة
و`--purge` بيسيبها، `--repair` بيصلّحها، والصورة المتفضّية بتتعرض من R2.

⚠️ البادئة الصح اتأكدت فى التشغيل الحقيقى (٢٠٢٦-٠٩-٢٢): `ads-menoskar42.replit.app/maintenance/uploads/`
مش `/serviceflow/maintenance/…` — دى بترجّع ٣٠٢.

والبوابة الأهم: `X-Photo-Source`. لو النشر مش شايف أسرار R2، الصورة بتتعرض
من القاعدة فى صمت (اتجرّب: R2 واقع ← ٢٠٠ عادى). فقبل التفضية لازم `curl` على
الموقع المنشور يقول `r2` — وإلا التفضية هتوقّع كل الصور.

```
مهمة: نقل صور الصيانة القديمة من قاعدة PostgreSQL لـCloudflare R2.
المالك فوّضك تعملها كلها. كل الخطوات أوامر شِل وأزرار ريبليت — **مفيش أى
سرّ ولا مفتاح هتلمسه أو تشوفه.** الأسرار متحطّة خلاص واتأكدت.

القاعدة الذهبية: **الصورة بتفضل فى القاعدة لحد آخر خطوة.** مفيش حاجة بتتمسح
غير فى خطوة ٨، ومش هتوصلها غير لو كل اللى قبلها عدّى. لو أى خطوة طلعت
حاجة غير المكتوب هنا → **وقف وقول للمالك**، متكمّلش ومتحاولش تصلّح من عندك.

── ١) هات آخر كود ─────────────────────────────────────────────────────
مشروع sf (replit.com/@menoskar42/sf) ← تبويب Git ← Sync/Pull.
وبعدين فى الـShell:

    grep -c "X-Photo-Source" serviceflow/server/maintenance/app/app.js
    grep -c "REPAIR" serviceflow/scripts/migrate-photos-to-r2.cjs

الأول لازم يطلع ٤، والتانى ١ أو أكتر. لو طلع صفر → الـSync ماشتغلش، وقف.

── ٢) النشر ───────────────────────────────────────────────────────────
اضغط Republish. لو ظهرت شاشة فيها «Generated migrations» افتحها واتأكد
إنها **فاضية أو مافيهاش ولا DROP COLUMN ولا DROP TABLE**. ولو ظهرت شاشة
«Detected potential conflicts» أو فيه أى DROP → **Cancel ووقف** وقول
للمالك. متضغطش Approve على حاجة فيها DROP أبداً.
استنى لحد ما الحالة تبقى Live.

── ٣) شِل جديد واختبار R2 ─────────────────────────────────────────────
اقفل تبويب الـShell وافتح واحد جديد (الأسرار بتتقرا وقت فتح الشِل)، ونفّذ:

    node serviceflow/scripts/migrate-photos-to-r2.cjs --check

لازم «✅ R2 شغّال». غير كده → وقف.

── ٤) القياس ──────────────────────────────────────────────────────────
    node serviceflow/scripts/migrate-photos-to-r2.cjs --dry

أول سطر لازم يقول القاعدة neondb ومن SERVICEFLOW_DATABASE_URL.
و«لسه فى القاعدة بس» لازم يكون حوالى ١٧٥٨ صورة. رقم صغير أو صفر أو
«مفيش جدول photos» → قاعدة غلط، وقف. انسخلى الناتج.

── ٥) الرفع (مابيمسحش حاجة) ───────────────────────────────────────────
    node serviceflow/scripts/migrate-photos-to-r2.cjs

بياخد دقايق. بيكتب «… ٥٠ صورة، … ١٠٠ صورة». لو الشِل فصل فى النص: افتح
شِل جديد وشغّل **نفس الأمر** — بيكمّل من حيث وقف. لو آخره قال «فشل N»
شغّله مرة كمان؛ لو لسه فيه فشل، كمّل عادى وقول للمالك أسماء الصور.

── ٦) التحقق (قراءة بس) ───────────────────────────────────────────────
    node serviceflow/scripts/migrate-photos-to-r2.cjs --verify

بيقارن كل صورة على R2 بالأصل اللى فى القاعدة (SHA256). لازم «فشل 0».
لو فيه فشل:
    node serviceflow/scripts/migrate-photos-to-r2.cjs --repair
    node serviceflow/scripts/migrate-photos-to-r2.cjs --verify
لو لسه فيه فشل بعد كده → **وقف قبل خطوة ٨**.

── ٧) 🔴 البوابة: الموقع المنشور بيقرا من R2 فعلاً؟ ─────────────────
ده أهم فحص. لو النشر مش شايف R2، الصور بتتعرض من القاعدة فى صمت — وبعد
التفضية كلها هتقع. فهات اسم صورة اتنقلت:

    psql "$SERVICEFLOW_DATABASE_URL" -tAc "SELECT filename FROM maintenance.photos WHERE storage_key IS NOT NULL AND data IS NOT NULL ORDER BY id LIMIT 1"

وجرّبها على الموقع المنشور (حطّ الاسم مكان FILENAME):

    curl -s -o /dev/null -D - "https://ads-menoskar42.replit.app/maintenance/uploads/FILENAME" | grep -iE "^HTTP|x-photo-source"

لازم يطلع السطرين دول:
    HTTP/... 200
    x-photo-source: r2

  • لو «x-photo-source: db» → النشر مش بيقرا من R2. **وقف، متكمّلش لخطوة ٨.**
  • لو مفيش سطر x-photo-source خالص → النشر لسه على الكود القديم. وقف.
  • لو الرد ٤٠٤ أو صفحة HTML → البادئة غلط. افتح أى صفحة بوكس فى موقع
    الصيانة من المتصفح، دوس كليك يمين على أى صورة ← Copy image address،
    وخد منه البادئة الصح، وجرّب تانى.

── ٨) التفضية (الخطوة الوحيدة اللى بتمسح) ─────────────────────────────
**بس لو خطوة ٦ قالت «فشل 0» وخطوة ٧ قالت «x-photo-source: r2».**

    node serviceflow/scripts/migrate-photos-to-r2.cjs --purge

بيعيد المقارنة بالـSHA256 لكل صورة لحظتها، ومابيفضّيش غير اللى مطابقة.
انسخلى السطر الأخير.

── ٩) رجّع المساحة ────────────────────────────────────────────────────
    psql "$SERVICEFLOW_DATABASE_URL" -c "VACUUM (FULL, ANALYZE) maintenance.photos"

بياخد قفل لدقيقة أو اتنين والصور مش هتتعرض خلالها. لازم يرد «VACUUM».

── ١٠) الحالة النهائية والتأكيد ───────────────────────────────────────
    node serviceflow/scripts/migrate-photos-to-r2.cjs --dry

المفروض «فى R2 بس» حوالى ١٧٥٩ و«لسه فى القاعدة بس» صفر أو قريب منه.
وأعد curl خطوة ٧ على نفس الصورة — لازم لسه ٢٠٠ و r2 (دلوقتى مالهاش نسخة
فى القاعدة، يعنى R2 هو المصدر الوحيد). وافتح صفحة بوكس فيها صور قديمة
فى المتصفح واتأكد إنها بتتعرض.

🚫 الخطوط الحمرا:
- متعرضش ولا تكتب قيمة أى سرّ. متعدّلش أى سرّ.
- متعدّلش أى كود، ومتشغّلش أى أمر غير اللى فوق.
- متلمسش كلاودفلير خالص (DNS / Workers / الباكِت).
- متعملش Approve على أى نشر فيه DROP.
- متكمّلش لخطوة ٨ لو ٦ أو ٧ ماعدّوش — مهما كان السبب.

التقرير: ناتج كل خطوة (السطور المهمة) و✅ أو ❌ قدامها.
```

## بعد ما الإكستنشن يخلّص — خطوات المالك

1. **Republish** فى ريبليت. ساعتها:
   - العمود `storage_key` بيتضاف لجدول `maintenance.photos` لوحده.
   - أى صورة **جديدة** الفنى يرفعها بتروح R2 على طول.
   - ⚠️ العمود ده **مش** فى `shared/schema.ts` ولا فى `ensureSchema()` بتاع
     `server/db.ts` (جداول الصيانة تطبيق CJS مستقل) — يعنى **مفيش تحذير
     DROP COLUMN** متوقّع فى شاشة النشر من الشغل ده.
2. **اتأكد إن الصور الجديدة شغّالة**: ارفع صورة من حساب فنى صيانة واضغط
   عليها تتعرض. لو ظهرت، يبقى R2 شغّال.
3. **نقل الصور القديمة** من شِل ريبليت، بالترتيب ده وبس:

   ```
   node serviceflow/scripts/migrate-photos-to-r2.cjs --dry      # عدّ وحجم بس
   node serviceflow/scripts/migrate-photos-to-r2.cjs            # رفع — data مابيتلمسش
   node serviceflow/scripts/migrate-photos-to-r2.cjs --verify   # مقارنة SHA256 لكل صورة
   node serviceflow/scripts/migrate-photos-to-r2.cjs --purge    # data = NULL — بعد verify بس
   ```

   🔴 **`--dry` هو اللى بيقولك إنت واقف على أنهى قاعدة.** شِل ريبليت بيوصل
   لقاعدة غير اللى الموقع بيقرا منها (مزلق رقم ١ فى `HANDOVER.md`). لو طلع
   **~١٧٤٨ صورة / ~٧٥٦ ميجا** كمّل. لو طلع رقم صغير أو صفر، إنت على الـdev —
   **قف**.

4. بعد `--purge`: `VACUUM (FULL, ANALYZE) photos;` عشان المساحة ترجع فعلاً.
