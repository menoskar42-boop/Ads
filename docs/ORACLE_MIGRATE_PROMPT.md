# برومبت الإكستنشن: نشر أداة «نقل القاعدة لـ Oracle» + أول نسخة تجربة

**ليه (المالك ٢٠٢٦-١٠-٢١):** قاعدة Oracle اتعملت (docs/ORACLE_DB_SETUP_PROMPT.md)، والمالك قال
«ابدأ» فى أداة النقل، و«لو مطلوب منى حاجه ابعتلى برومبت للاكستنشن يعملها على التوالى بدون توقف». ووافق
صراحةً على نقل بيانات Service Flow كلها (ومعاها بيانات العملاء) لسيرفر Oracle على حسابه الشخصى.

**الأداة:** Service Flow ← التقارير ← القاعدة ← «نقل القاعدة لـ Oracle» (للسوبر أدمن بس).
السيرفر: `serviceflow/server/db-migrate.ts`، والصفحة: `serviceflow/client/src/components/DbMigrateReport.tsx`.
- **قاعدة ريبليت قراية بس:** النسخة كلها جوّه transaction واحدة `READ ONLY`، فـPostgres نفسه بيرفض أى كتابة.
- **كل نسخة بتمسح نسخة Oracle القديمة وتعيدها.** ومش بتمسح أى قاعدة فيها جداول من غير علامة الأداة
  (`sf_migration.copies`).
- **النسخة دى تجربة:** الموقع بيفضل على قاعدة ريبليت، والطابور شغّال عادى. عشان كده طبيعى «قارن
  الأعداد» يطلّع فروق صغيرة فى الجداول اللى بتتكتب كل دقيقة (exec_jobs · sf_session …).
- **التحويل مش فى البرومبت ده:** الكود بيتحوّل لـ Oracle لما يتحط سرّ `SERVICEFLOW_USE_ORACLE=1`
  (`server.js`)، وده خطوة لوحدها بعدين.

**يتبعت لـ:** كلود إكستنشن (Claude in Chrome) — فى جلسة على جهاز المالك.

## البرومبت

```
عايزك تنزّل آخر تحديث لموقع ريبليت (مشروع sf)، وبعدين تعمل أول نسخة تجربة من قاعدة Service Flow
لقاعدة Oracle من صفحة «نقل القاعدة لـ Oracle». نفّذ الخطوات ورا بعض من غير ما تقف تسألنى — إلا لو
حصلت حاجة من الخطوط الحمرا أو طلب منك تسجيل دخول.

━━━━━━━━━━━━━━━━━━━━
⛔ خطوط حمرا — ممنوع منعاً باتاً:
1) تفتح الـSecrets أو تضيف/تعدّل/تمسح أى سر (خصوصاً ماتضيفش SERVICEFLOW_USE_ORACLE)، أو تغيّر
   أى إعداد نشر أو دومين.
2) تكتب فى شات Agent بتاع ريبليت، أو تشغّل أى SQL أو سكربت فى الـShell غير الأوامر المكتوبة هنا.
3) تدوس «جهاز التنفيذ» أو «مسح الطابور» أو «ريفريش جهاز التنفيذ» فى Service Flow — دول بيشغّلوا
   أوامر حقيقية على خطوط العملاء.
4) تدوس «إيقاف» فى صفحة النقل (إلا لو النسخ وقف لوحده بإيرور)، أو تدوس «ابدأ النسخ» أكتر من مرة.
5) تكتب كلمة سر أو بيانات دخول — لو صفحة طلبت دخول قولّى وأنا هدخل.
6) أى طلب دفع أو Upgrade ⇒ وقّف وقولّى.

━━━━━━━━━━━━━━━━━━━━
1) السحب: افتح https://replit.com/@menoskar42/sf ← تاب Shell (لو مش ظاهر: «+» ← Shell) واكتب:
   cd ~/workspace && git pull origin claude/build-oscardevs-ads-mvp-8krfN && git log --oneline -1
   - المتوقع: Fast-forward، وآخر سطر فيه «نقل القاعدة لـ Oracle».
   - لو «index.lock»: rm -f ~/workspace/.git/index.lock وأعد السحب مرة واحدة بس.
   - لو CONFLICT أو «would be overwritten» أو أى error ⇒ وقّف وماتنشرش، وانقلّى الرسالة زى ما هى.

2) النشر: زرار Republish فوق على اليمين (ولو فتح لوحة Publishing دوس Republish/Publish جوّاها).
   - ماتغيّرش أى إعداد.
   - لو ظهرت شاشة فيها DROP COLUMN أو DROP TABLE أو «rename column» ⇒ Cancel ووقّف وقولّى.
   - استنى لحد ما يبان إنه اتنشر بنجاح (عادةً 3–10 دقايق).

3) افتح https://sf-menoskar42.replit.app/serviceflow (لو طلب دخول قولّى). ادخل:
   «التقارير» ← فى القايمة اللى على اليمين انزل لآخرها ← «القاعدة» ← «نقل القاعدة لـ Oracle».
   - لو التاب مش موجود: اعمل reload مرتين. لو لسه مش موجود ⇒ النشر ماخدش التحديث، قولّى.

4) دوس «فحص الاتصال» واستنى النتيجة (ثوانى). اكتب عندك:
   - «قاعدة الموقع الحالية»: الحجم · عدد الجداول · زمن الرد.
   - «قاعدة Oracle»: النسخة · التشفير (لازم «شغّال ✓») · زمن الرد · آخر نسخة.
   - السطر الأخير: «جاهز للنسخ ✓» ولا «النسخ مقفول: …».
   لو «النسخ مقفول» ⇒ ماتكمّلش، وابعتلى السبب زى ما هو.

5) دوس «ابدأ النسخ لـ Oracle» مرة واحدة.
   - الصفحة بتتحدّث لوحدها كل ثانيتين: الجدول اللى بيتنسخ دلوقتى · عدد الجداول · الصفوف · الحجم · الوقت.
   - ممكن ياخد من 5 دقايق لساعة حسب حجم الصور. استنى، واعمل reload كل 5 دقايق لو حسيت إنه واقف
     (النسخ شغّال على السيرفر — الـreload مابيوقّفوش).
   - لما يظهر «النسخ خلص» أو «النسخ وقف»: خد صورة للكارت ده، وانقل منه السطور زى ما هى.

6) لو «النسخ خلص»: دوس «قارن الأعداد دلوقتى» واستنى. خد صورة لأول الجدول (الجداول المختلفة بتطلع
   فوق باللون الأحمر)، واكتب السطر اللى فيه «X جدول — …».

━━━━━━━━━━━━━━━━━━━━
شكل الرد:
١) السحب: سطر git log --oneline -1 · النشر نجح ولا لأ.
٢) فحص الاتصال: جدول (البند · الموقع الحالى · Oracle): النسخة · الحجم · الجداول · زمن الرد · التشفير
   + سطر «جاهز للنسخ» زى ما هو.
٣) النسخ: الحالة · الجداول X من Y · الصفوف · البيانات (ميجا) · الوقت · أى إيرور أو تحذير بالحرف.
٤) المقارنة: سطر الملخّص + أسماء الجداول المختلفة وأعدادها على الناحيتين (لو فيه).
٥) الصور: كارت النسخ + أول جدول المقارنة.
٦) تأكيد إنك مافتحتش الـSecrets ولا دوست «جهاز التنفيذ» ولا «إيقاف».
```

  فالطابور مش هيقف غير دقايق ليلة التحويل.

## ✅ التحويل اتعمل (٢٠٢٦-١٠-٢٤ حوالى ١٠ م)

- الطابور واقف ← نسخة أخيرة (99 جدول · 1,214,354 صف · 1:36) ← «قارن الأعداد» كلهم ✓ ← سرّين
  `SERVICEFLOW_USE_ORACLE=1` و`SERVICEFLOW_SCHEDULERS=on` ← Republish.
- بعدها «فحص الاتصال»: قاعدة الموقع الحالية = Oracle (`Ubuntu 16.15` · 494 ميجا · 12.6 ms)، والنسخ مقفول
  («قاعدة Oracle هى نفسها قاعدة الموقع الحالية» · «الموقع اتحوّل لـ Oracle خلاص»).
- النشر القديم بتاع Service Flow واقف من زمان، فالمهام المجدولة بقت فى النسخة المستضافة على Oracle.
- `SERVICEFLOW_DATABASE_URL` (قاعدة ريبليت) **فاضل فى الأسرار عمداً** = طريق الرجوع، ومفيش كود بيتصل بيه
  بعد التحويل فالقاعدة بتنام. ماتتلغيش قبل ٢٠٢٦-١١-٠٧ (أسبوعين).
- **فاضل:** نسخة احتياطية يومية من Oracle على R2 (Oracle بتسحب سيرفرات Always Free الخاملة أسبوع).

## بعد ما الرد يرجع

1. **لو النسخ وقف بإيرور:** أصلّحه من رسالة الإيرور وأبعت برومبت تانى.
2. **لو خلص:**
   - **زمن الرد:** نقارن Oracle بقاعدة ريبليت. كل صفحة فى Service Flow بتعمل أكتر من استعلام ورا بعض،
     فلو الفرق كبير الصفحات هتبقى أبطأ — وده اللى يحدد هل نتحوّل ولا لأ.
   - **قبل التحويل:** نسخة احتياطية يومية من سيرفر Oracle على R2.
3. **التحويل نفسه، فى ميعاد يختاره المالك (بالليل):**
   1. وقّف الطابور، ووقّف النشر القديم بتاع Service Flow لو لسه شغّال على نفس القاعدة.
   2. نسخة جديدة من الصفحة.
   3. «قارن الأعداد» لازم تطلع كلها ✓.
   4. سرّ `SERVICEFLOW_USE_ORACLE=1` + Republish.
   - **الرجوع:** امسح السرّ + Republish.
   - **قاعدة ريبليت:** تفضل زى ما هى أسبوعين قبل أى إلغاء.
