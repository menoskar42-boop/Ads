# 🏋️ خطة تطوير: نظام إدارة الجيم والصالات (Gym / Fitness Vertical)

> فكرة من صاحب المالك (تيك توك): «صاحب الجيم أو الصالون بيخسر فلوس من اشتراكات
> بتخلص من غير ما حد يجدد». الحل: نظام حجز واشتراكات ذكي يدير الحضور والتجديد
> لوحده. ده **vertical جديد على OscarDevs** زي (shop / clinic / pharmacy / orders):
> `page_type = 'gym'` → لكل جيم `slug.oscardevs.com` + لوحة إدارة خاصة + اشتراك.

---

## 🎯 الفكرة الأصلية (من البوست)
1. **تجديد تلقائي:** تنبيه للعميل قبل انتهاء اشتراكه بأيام كافية.
2. **حجز ذاتي:** العميل يحجز حصته/الكلاس من غير ما يتصل بالجيم.
3. **تقرير دخل وحضور:** إيرادات + نسبة تجديد الاشتراكات بضغطة زر.

### مميزات عندهم **مش في الفكرة الأصلية** — نضيفها:
- **تسجيل حضور / كنترول دخول** (QR / باركود / كارت عضوية / بصمة) — «العضو يعمل Check-in».
- **إدارة الكلاسات والجدول** (سعة قصوى، قائمة انتظار Waitlist، تعيين مدرب، منع التعارض).
- **باقات اشتراك متعددة** (شهري/ربع سنوي/سنوي + تجميد/إيقاف مؤقت Freeze).
- **حصص التدريب الشخصي (PT)** + تتبّع باقات الحصص (10 حصص → تنقص مع كل حضور).
- **CRM واحتفاظ** (أعضاء في خطر التسرّب At-risk، نسبة الاحتفاظ Retention، تنبيهات).
- **نقطة بيع (POS)** — بيع مكمّلات/مشروبات/عضويات/ملابس.
- **إدارة المدرّبين + العمولات** (نصيب المدرب من الحصص/المبيعات).
- **بوابة العضو / تطبيق** — العضو يشوف اشتراكه، يحجز، يعمل Check-in، يتابع تقدّمه.
- **قياسات الجسم وتتبّع التقدّم** (وزن/دهون/محيطات + صور before/after) — مهم لكمال الأجسام.
- **خطط تمرين وتغذية** (يربط بـ«مميزات دكتور التغذية» المؤجّلة في الذاكرة).
- **إحالات وعروض** (Referral + كوبونات) — نعيد استخدام نظام الكوبونات الموجود.
- **فوترة/مدفوعات** — نعيد استخدام بوابات الدفع (Paymob) + الدفع النقدي.

## 🗺️ خطة التنفيذ على مراحل (نفس أسلوب roadmap أمازون)

### 🟢 المرحلة 1 — الأساس (Vertical + الصفحة العامة)
- `page_type = 'gym'` في companies + التوجيه في tenant.js.
- الصفحة العامة الاحترافية (`tenant_gym.ejs`) — Hero + باقات + كلاسات + مدرّبين +
  معرض + آراء + CTA «اشترك / احجز جولة». (التصميم من برومبت كلود ديسين المرفق.)
- schema أساسي: `gym_settings`, `gym_plans` (الباقات), `gym_trainers`, `gym_classes`.
- SEO: `LocalBusiness`/`HealthAndBeautyBusiness` + `SportsActivityLocation` schema،
  عنوان ≤ 60، صور بـalt، noindex للتجريبي.

### 🟢 المرحلة 2 — الأعضاء والاشتراكات
- `gym_members` + `gym_subscriptions` (باقة، بداية، نهاية، حالة، تجميد).
- تجديد تلقائي + **تنبيه قبل الانتهاء بأيام** (Web Push — البنية موجودة).
- لوحة الأدمن: إضافة عضو، بيع اشتراك، تجديد، تجميد/إلغاء.

### 🟢 المرحلة 3 — الحضور والحجز الذاتي
- Check-in (QR/كود العضو) + سجل حضور `gym_attendance`.
- حجز الكلاسات ذاتياً (سعة + Waitlist) `gym_bookings`.
- حصص PT + تتبّع الباقة.

### 🟢 المرحلة 4 — التقارير والاحتفاظ
- تقرير دخل + نسبة تجديد + حضور شهري + أعضاء في خطر التسرّب.
- أكثر الكلاسات حضوراً + أداء المدرّبين.

### 🟡 المرحلة 5 — POS + العمولات + الإحالات
- بيع منتجات/عضويات، عمولة المدرّب، أكواد إحالة/كوبونات.

### 🟡 المرحلة 6 — تتبّع التقدّم + خطط التمرين/التغذية
- قياسات + صور before/after + خطط (يربط بمميزات دكتور التغذية).

> **كل ميزة ليها سويتش أدمن** (زي المتجر)، و**كل schema داخل `initDb` بـIF NOT EXISTS**،
> ونختبر كل مرحلة على Postgres قبل الـcommit، وبرومبت QA كل مرحلة أو اتنين.
